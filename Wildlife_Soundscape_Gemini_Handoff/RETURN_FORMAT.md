# Gemini Return Format

After each implementation phase, Gemini should report:

## Phase
`P# - name`

## Files modified
- exact relative paths

## Files created
- exact relative paths

## Behavior changed
- concise functional summary

## Interfaces preserved
- relevant public contracts

## Tests run
- exact command
- pass/fail count

## Known limitations
- only real remaining limitations

## Next phase
- one line

If Gemini cannot verify an API or scientific definition, it should stop that
specific change and report the uncertainty instead of inventing behavior.
